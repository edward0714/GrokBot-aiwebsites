# GrokBot_AI Service

繁體中文（台灣）家計帳本儀表板的**公開合成資料示範**。整個網站是單一靜態 HTML 檔案，不需要伺服器程式、不需要登入，也不連結任何外部服務。

> **公開示範聲明**
>
> - 這是公開的靜態示範網站，**不是**真實或已同步的帳本。畫面上的交易、帳單、商家與郵件編號全部是虛構的合成資料。
> - 您做的任何變更（新增、編輯、指定帳本、匯入、標記付款）**只儲存在您目前使用的瀏覽器的 localStorage**，不會上傳到任何地方；換瀏覽器、換裝置或清除網站資料後就會消失。
> - 本站**沒有帳號、沒有登入，也沒有私人雲端儲存**。
> - **請勿輸入或匯入真實、敏感的財務資料。**
> - 沒有分析追蹤、沒有對外網路請求，也不收集帳號、密碼或任何金鑰。

## 功能

- **月份總覽**：選擇月份、幣別（新台幣／日圓／美元）與帳本（個人／家庭／公務／待確認），顯示總支出、退款（以負數表示）與淨支出，並逐筆核對「總支出 + 退款 = 淨支出」。
- **幣別不混算**：三種幣別各自計算，不做匯率換算，也不合併成單一總額。
- **兩種退款歸屬檢視**
  - 「依交易日期（示範）」：每筆交易依紀錄上的日期歸入月份；之後月份的退款不會回頭改變先前月份。
  - 「原始消費調整」：已連結原始消費的退款，歸回原始消費的月份，方便看某筆消費最後實際花了多少。
- **互動圖表**：類別占比環圈圖、每日消費與退款長條圖（附表格檢視）、近 6 個月淨支出趨勢（點選即可切換月份）。
- **交易明細**：搜尋、篩選、排序，新增與編輯範例交易；退款以負數儲存，可連結同幣別的原始消費。
- **帳本需明確指定**：帳本與類別是分開的欄位，系統不會依商家名稱猜測用途；「待確認」的交易必須由使用者選擇帳本並勾選確認。
- **缺漏資料透明處理**：金額或日期未知時顯示「待補」，不當作 0，也不猜測；僅授權（預授權）的交易不計入已入帳合計。每個月份都會列出被排除的項目與原因。
- **匯入預覽（僅在瀏覽器內處理）**：貼上 JSON 範例資料後，會檢查郵件編號（messageID）重複、批次內重複、疑似重複與無效資料，確認後才加入；匯入的交易一律先放在「待確認」帳本。
- **帳單提醒（模擬）**：以固定的示範日期計算到期、提醒與逾期狀態。
- **瀏覽器內儲存與重設**：資料有版本號，版本不符或資料損壞時會改回原始範例資料；重設前會再次確認。

## 示範版的限制

- **沒有銀行驗證或整合**：不連結銀行、信用卡、電子郵件或試算表。「依交易日期（示範）」使用的是範例紀錄上的日期，**不是經銀行獨立驗證的實際金流或付款（扣款）日期**。
- **沒有真實連線、提醒或付款**：帳單狀態只是模擬，不會寄送通知；「標記已付款」只改變瀏覽器裡的範例資料，不會進行任何付款。
- **資料只在目前瀏覽器**：沒有帳號、沒有雲端同步、沒有多人共用；清除瀏覽器網站資料後，變更就會消失。
- 空白的圖表或清單不代表實際支出為 0，只代表範例資料在該條件下沒有可計入的交易。
- 示範版不提供刪除交易，可用「重設示範資料」還原。

## 計算方式

只計入同時符合以下條件的交易：幣別相符、帳本相符、狀態為已入帳、日期已知、金額已知、歸入所選月份。

```
總支出 = 金額大於 0 的交易加總
退款   = 金額小於 0 的交易加總（維持負數）
淨支出 = 總支出 + 退款
類別占比 = 該類別消費 ÷ 總支出（退款另列，不計入占比）
```

選擇「全部帳本」時會包含「待確認」帳本中已入帳的金額；選擇特定帳本時，待確認交易不計入，並在排除清單中說明。
